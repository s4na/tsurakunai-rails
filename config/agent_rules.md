# Rails変更の共通ルール

Railsの実装・修正・レビューでは、プロジェクトルートの`RAILS_TEAM_POLICY.md`を先に読み、変更に適用する規約を確認する。チームの明示規約と例外を優先し、既存コードやlintのOFFだけから新しい許可を推定しない。

- 各規約の「必須の形・契約を満たす」と「禁止形を使わない」の両方を守る。必須条件を任意の助言へ弱めない。
- 実装では両方を満たす形を作り、レビューでは必須条件の欠落と禁止形の使用を両方確認する。規約違反はID・対象・欠落または禁止形・置き換え先を示し、動作不良とは分ける。
- lint・既存テストの成功だけで規約適合としない。必要な責務・入力・公開API・失敗契約があることも確認し、未確認を合格へ読み替えない。
- 導入済みなら`tsurakunai-rails-implement`または`tsurakunai-rails-review`スキルを使い、同じ規約で実装・検証・レビューを進める。スキルがない場合も規約の両方向を守る。
- 必要な認証・保存・commitの既存契約を維持し、lintを通す目的で例外やOFFを増やさない。新しい例外は対象・理由・代替保証を規約と設定へ残す。

変更に関係する項目だけに適用し、未変更領域の一括改修や新しい外部操作の権限を要求しない。
